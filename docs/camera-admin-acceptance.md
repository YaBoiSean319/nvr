# Camera administration acceptance record

Ticket #75 adds authenticated Playwright journeys backed by the running FastAPI application, temporary SQLite/recording/credential stores, deterministic camera fixtures, a loopback ONVIF responder, and generated RTSP test media. CI installs the pinned Playwright package and Chromium, runs the browser journeys, and validates two report conditions: serialized `webServer.env` keys match the fixture allowlist, and the injected runner-only sentinel is absent. It uploads the report, traces, screenshots, videos, and sanitized 200-camera measurements as the `camera-admin-browser-acceptance` artifact only when both conditions pass, including when a browser journey fails.

The measurements JSON is initialized before the Playwright server or browser starts. If the 200-camera measurement test does not complete, it explicitly says `not-collected`, includes zero samples, and leaves the deployment gates unchecked; it never substitutes guessed timings. On completion it records application/browser/runner versions, workload, ten filter samples, five selected-panel samples, conventional median p50 and nearest-rank p95, browser and failed-request counts, inventory media-request count, owner, result, and artifact evidence. The test report JSON is also pre-seeded so a failed web server or earlier journey still leaves a stable artifact path; Playwright replaces it with its normal report when the reporter completes. The CI report validator checks only the serialized `webServer.env` key allowlist and absence of the injected runner-only sentinel. If either condition fails, the workflow skips artifact upload.

The browser suite uses only deterministic synthetic camera names, documentation-only IPs, loopback stream URLs, and a fixture-only password; it does not use real camera credentials, tenant data, or footage. The fixture manifest and isolated credential key live in the temporary test directory and are removed after the Playwright process exits.
