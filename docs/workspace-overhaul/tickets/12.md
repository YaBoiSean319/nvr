# [Workspace 12] Organize system settings with real saves and complete access

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/61

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Replace the long settings page with discoverable categories and working configuration/status flows while preserving supported functionality and permissions.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Provide General, Appearance and Branding, Users & access, Recording & storage, Notifications, Integrations and Diagnostics, with category deep links and one coherent editor at a time.
- [ ] Preserve timezone/date/12–24-hour formatting with previews and safe validation, sessions, supported identity/SSO status/setup access, storage/retention, alerts/webhooks, heartbeat, AI/integration and diagnostics access.
- [ ] Clearly describe environment-configured SSO and host backup procedures; do not invent in-app secret saves or backup/restore controls.
- [ ] Use explicit saves, immediate busy feedback, field-level errors, persistent actionable failures and unsaved-edit protection. No placeholder successful actions.
- [ ] Operators retain authorized read/operational data but cannot mutate configuration or access administrator sessions/diagnostics; server enforcement backs navigation restrictions.
- [ ] Persist real settings across refresh/restart without changing canonical UTC, camera clocks, schedule interpretation or already queued export display settings.
- [ ] Browser/API verification maps every supported old settings function to a reachable replacement and exercises success/failure/permission paths.

## Verification

Verify through the authenticated API/browser boundary with deterministic camera fixtures and generated playable media as applicable. Preserve recording priority, role/ownership checks, retention/holds, source-time/evidence semantics and existing supported workflows. Do not accept markup strings, successful HTTP responses alone, or mockup behavior as proof that a user workflow works.
