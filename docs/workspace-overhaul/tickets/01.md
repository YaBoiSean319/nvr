# [Workspace 01] Ship the application shell with a real Live viewing journey

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/50

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Deliver the approved full-window shell and a real login-to-Live workflow while retaining access to all existing operational and administrative functions. Any frontend prefactoring is incremental and belongs inside this working slice.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Live is the landing destination; compact top navigation exposes Live, Playback, Cameras and Settings with server-enforced administrator restrictions for the latter two.
- [ ] The shell has a collapsible/resizable contextual browser, dominant video canvas and compact persistent status area; it does not relocate old stacked forms as the final design.
- [ ] An authorized user can select a real fixture camera and receive authenticated video; removed or logged-out sessions release viewer resources.
- [ ] Define explicit Live/Playback workspace state and incremental module boundaries while keeping existing recording/authentication/API routes working.
- [ ] Use neutral theme tokens, consistent controls and dark/light/system appearance; retain usable navigation to existing functions while later slices replace their presentation.
- [ ] Browser tests verify login, navigation, one-camera viewing, sign-out/resource release and operator/admin access instead of relying on HTML ID assertions.

## Blocked by

None (can start immediately).

## Verification

Verify through the authenticated API/browser boundary with deterministic camera fixtures and generated playable media as applicable. Preserve recording priority, role/ownership checks, retention/holds, source-time/evidence semantics and existing supported workflows. Do not accept markup strings, successful HTTP responses alone, or mockup behavior as proof that a user workflow works.

## Post-merge testing required

- [ ] Verify local and configured SSO login, actual media display, logout and role navigation in the target browser fleet.

Record application version, environment/workload, steps, test owner and result/evidence. Leave unrun checks unchecked; distinguish implementation completion from deployment qualification.
