# [Workspace 05] Build the Playback workspace with a shared interactive timeline

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/54

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Move recorded-footage investigation into a coherent workspace with real authenticated media, a shared clock and automatic camera application. This slice works honestly within the current backend camera bound until the separate capacity slice lifts it.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Playback has a dominant video grid, shared transport and aligned per-camera timeline rows for recording coverage, motion/AI markers and missing/failure/uncertain intervals.
- [ ] Sidebar camera toggles automatically apply at the current range/time, preserving play/pause, marks and unaffected players; newly selected cameras join the shared clock.
- [ ] Support date/time jump, validated range changes, scrub, zoom, pan and Fit Range. Start a new investigation with the preserved past-hour/site-timezone defaults.
- [ ] Open in Playback deliberately includes the chosen live camera while retaining existing investigation context; when full, require an explicit replacement/subset choice.
- [ ] Live/Playback state is independent. Release inactive viewing/decoding resources while retaining restoration metadata; no duplicate connections on return.
- [ ] Coalesce rapid seek inputs, cancel superseded requests and reject out-of-order results; distinguish immediate UI feedback from actual decoded-frame completion.
- [ ] Keep existing range/admission bounds visible and consistent during incremental delivery; do not advertise unimplemented 16-camera support.
- [ ] Test staggered/generated footage, gap states, timezone/DST range validation, rapid seek races, membership changes and mode restoration through the real browser/API seam.
