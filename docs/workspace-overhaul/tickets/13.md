# [Workspace 13] Implement persistent application branding with safe assets

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/62

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Deliver actual administrator-controlled app name, colors and logos in Appearance and Branding, with coherent sign-in/application presentation and durable settings/assets.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Configure a trimmed 1–80-character plain-text application name, restrained primary/accent colors, primary logo, optional light/dark variants and a compact app icon, with light/dark previews.
- [ ] Provide draft-only preview, explicit Save, remove/reset per asset and Reset to defaults. Failed save leaves prior published branding intact; successful settings/assets survive restart on existing durable storage without a required new Compose mount.
- [ ] Apply branding to sign-in/first-run shell, app header, browser document title and favicon where supported; preserve bounded aspect-ratio containers and default fallbacks for missing/failed assets.
- [ ] Accept decoded PNG/WebP/JPEG up to 2 MiB per file and 4096×4096 pixels; validate actual type/dimensions and reject corrupt, spoofed, oversized/decompression-abusive or executable content. No remote image URL, raw CSS/HTML or executable SVG input.
- [ ] Serve assets via managed IDs with correct content type/version/cache behavior. Publish only minimal branding before sign-in; never expose private settings, cameras, tenant details, sessions or secrets.
- [ ] Branding save/reset/upload are administrator-only, validated atomically and audited. Anonymous/operator mutation attempts fail at the API boundary.
- [ ] Keep legible dark/light/system appearance, focus and semantic warning/error/success cues; user theme preference remains distinct from site identity.
- [ ] Brand changes do not rename cameras, change SSO/roles or add footage watermarks/modify existing exports. Test malicious names/assets, draft isolation, cache refresh, reset/fallback, login/title rendering and persistence.

Record application version, environment/workload, steps, test owner and result/evidence. Leave unrun checks unchecked; distinguish implementation completion from deployment qualification.
