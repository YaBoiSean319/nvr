# [Workspace 03] Unify camera/group/view browsing and workspace restoration

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/52

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Find cameras and apply groups or personal/shared saved views in the current workspace, with secure persistence and explicit overflow handling.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Search credential-safe camera names/available addresses and group/view names; list cameras alphabetically with membership checks and health, and distinguish personal/shared views.
- [ ] Selection remains contextual to Live or Playback; browsing in Playback never unexpectedly sends the user to Live.
- [ ] Load an ordered deduplicated group/view immediately within capacity. More than 16 candidates opens an explicit subset chooser before application; no invisible truncation.
- [ ] Save camera identities/order and Auto/manual mode; use Save/Save as and dirty indicators, never overwrite on view load, and never store historical dates inside a saved view.
- [ ] Preserve per-user Live/Playback restoration metadata independently, with no credential persistence or automatic audible audio; migrate existing layouts without losing camera order.
- [ ] Personal view ownership and administrator-managed shared groups/views are enforced by the API. Browsing group membership does not silently alter recording-policy inheritance.
- [ ] Browser/API tests cover search by separate camera address, multi-group deduplication, overflow, refresh, missing/archived cameras and cross-user denial.
