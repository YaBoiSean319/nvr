# [Workspace 10] Add a visual weekly recording schedule editor

Canonical issue: https://github.com/YaBoiSean319/nvr/issues/59

## Parent

https://github.com/YaBoiSean319/nvr/issues/49

## What to build

Edit recording schedules through day/time bands and policy-source controls while preserving the existing effective recording behavior.

Design reference and implementation handoff: https://github.com/YaBoiSean319/nvr/tree/docs/workspace-overhaul-2026-10-22/docs/workspace-overhaul

## Acceptance criteria

- [ ] Use visual weekly motion/continuous/disabled blocks with add/edit/move/remove and precise keyboard/time-field alternatives; routine editing requires no JSON.
- [ ] Show group inheritance, per-camera overrides and effective policy source; removing an override restores inherited behavior.
- [ ] Preserve ISO weekday/local-time meaning, start-inclusive/end-exclusive boundaries, overnight intervals belonging to their start day, overlap rejection and existing supervisor application bounds.
- [ ] Preserve IANA timezone and spring-forward/repeated fall-back behavior; changing display formatting does not rewrite schedule or camera clocks.
- [ ] Reject invalid edits with field-level errors and preserve the last saved policy on failure; survive reload/restart and round-trip old schedules without semantic changes.
- [ ] Operators can inspect effective policy but cannot mutate it; verify persisted API policy and boundary-driven recording behavior with deterministic time fixtures.
